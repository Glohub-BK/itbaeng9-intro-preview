# IT뱅구 — 128 BPM 모션그래픽 공통 제작 프롬프트

IT뱅구는 AI를 실제 영상·콘텐츠·기록·업무에 활용하는 과정을 함께 배우는 한국어 채널이다. 제공한 프로젝트 기록을 소재로, 시선을 붙잡는 30~40초 채널 소개 모션그래픽을 직접 코드로 제작하라.

기존 스킬, SKILL.md, 템플릿, 레지스트리, 이전 프로젝트의 모션 코드, 프리셋을 사용하지 말라. HyperFrames·GSAP·Remotion·Three.js 등 모션 프레임워크도 사용하지 않는다. vanilla JavaScript, Canvas 2D와 직접 작성한 수학 함수만으로 새로운 화면과 움직임을 만든다. 외부 이미지·영상·음성 생성 서비스 호출, 유료 생성, 새 TTS와 립싱크는 하지 않는다. 제공된 폰트와 음악은 입력 에셋으로 사용할 수 있다.

## 동일하게 고정할 조건

- 1920×1080, 16:9, 60fps, 정확히 37.5초.
- 128 BPM, 1박=0.46875초, 80박=20마디, 4/4박자.
- 동일한 inputs/audio/master.mp3 또는 master.wav 사용. 오디오를 늘이거나 속도를 바꾸지 않는다.
- Pretendard Regular 400 / Bold 700. inputs/assets/fonts에 있는 파일을 사용하고 글자 마스크를 만들기 전에 폰트를 실제로 로드한다.
- 팔레트: 거의 검정 #10110f, 따뜻한 아이보리 #f2f0e6, 라임 #c8ff64, 금속 회색 #a8aaa3. 재질용 명암은 허용한다.
- 큰 한국어 타이포와 충분한 여백. 기본 안전 여백 100px. 보조 문구는 원본 화면 기준 30px 이상. 마지막 IT뱅구 이름은 크고 정확하게 표현한다.
- 인물·아바타 출연 없음. 이번 소개 필름은 음악과 모션 중심이다. 미나의 제작 과정 나레이션은 후속 롱폼의 별도 범위다.
- 허위 프로젝트·수치·구독자 수·미실행 모델 결과·모델 순위는 넣지 않는다.

## 연출의 핵심

하나의 점이 선을 만들고, 선이 도형이 되고, 도형이 휴대폰·영상·파형·기록 연결망·자동화 흐름을 거쳐 다시 텍스트와 IT뱅구 이름이 되는 연속 변형을 보여준다. 장면마다 물체를 없애고 새 카드를 페이드 인하는 방식으로 대신하지 말라. 같은 윤곽과 점의 연속성이 보여야 한다.

안정된 순서의 같은 개수 윤곽점을 보간하거나 그에 준하는 직접 작성한 방법으로 형태를 변형한다. 입체감은 직접 만든 원근·크기·회전·재질과 그림자로 표현한다. 휴대폰 본체는 실제 아이폰에 가까운 가로:세로 71.5:149.6 비율을 유지한다. 폰 안에 AI 전문 채널 / IT뱅구 / @ITbaeng9를 정확히 표시한다.

박자·반박·세부 리듬에 반응하는 전환, 감속과 짧은 예비 동작, 킥에 맞는 카메라 반응을 설계한다. 반복되는 왼쪽 제목/오른쪽 물체 구도를 피하고, 중앙과 화면 전체를 차지하는 형태·큰 글자 전환·유용한 정지 자세를 섞는다. 글자는 읽을 때 선명해야 한다. 윤곽이 실제 글자 위치로 모이는 전환을 중간에도 최소 2회 구현한다. 글자의 마스크와 마지막 실제 글자의 폰트·크기·기준선을 일치시켜 겹쳐 보이지 않게 한다.

## 소재와 시간표

아래는 각 8박, 3.75초의 의미 구간이다. 내부에는 4박과 세부 박자에 맞는 변형을 자유롭게 설계한다. 구간 사이를 하드 컷으로 끊지 않는다.

| 박 | 시간 | 의미·주요 문구 | 형태의 흐름 |
|---|---|---|---|
|0–8|0–3.75|한 점의 상상|점 → 선|
|8–16|3.75–7.5|선을 넘어|선 → 다각형·링 → 글자|
|16–24|7.5–11.25|형태가 되고|입체 도형 → 휴대폰|
|24–32|11.25–15|영상이 되고|휴대폰 → 플레이어·타임라인 / AI 영상 제작|
|32–40|15–18.75|소리로 완성|타임라인 → 파형 / BGM·효과음|
|40–48|18.75–22.5|기록을 연결|파형 → 점과 연결선 / 옵시디언 기록|
|48–56|22.5–26.25|반복을 자동화|연결망 → 브라우저와 실행 경로 / Ego Lite|
|56–64|26.25–30|함께 배우고, 직접 만들자|연결 형태 → 타이포 모핑|
|64–72|30–33.75|다음 상상도, 함께|구독·좋아요와 형태의 피드백|
|72–80|33.75–37.5|AI 전문 채널 IT뱅구|점들이 정확한 IT뱅구 글자로 모여 마무리|

프로젝트 사실은 inputs/project-records.json에 한정한다. 인기·성과·공개 여부를 추가로 지어내지 않는다.

## 음악과 싱크

제공된 음악은 오리지널 128 BPM 하우스/일렉트로팝 트랙이다. 킥, 오프비트 베이스, 클랩, 하이햇, 코드와 플럭 멜로디, 전환 효과음이 들어 있다. 같은 음악을 사용해서 모션을 비교한다. 음악의 저작·편곡 점수는 이번 시각 비교 범위에 포함하지 않는다.

- 39박, 18.28125초 부근의 쉼 뒤 40박, 18.75초 드롭에 짧고 자연스러운 구독·좋아요 피드백을 넣는다. 기존 연결 형태 안에서 잠깐 반응하고 바로 다음 흐름으로 이어진다.
- 65박, 30.46875초: 구독 클릭 → 체크/구독 중.
- 67박, 31.40625초: 좋아요 반응.
- 이 클릭 소리는 제공된 음악에 이미 있으므로 중복 효과음을 더하지 않는다.
- 76박, 35.625초 부근에 채널 이름이 선명하게 정착하고, 끝까지 읽을 시간을 둔다.

## 구현과 산출물

1. 먼저 짧은 design-notes.md와 beat-map.json을 작성한다.
2. film.js / film.html을 새로 작성한다. window.renderFrame(t)는 시간만으로 같은 프레임을 만드는 함수여야 한다. 이전 프레임의 Canvas 상태, 임의 난수, 벽시계나 CSS 트랜지션에 의존하지 않는다. Canvas 상태를 매 프레임 초기화한다.
3. 폰트 로딩과 글자 마스크 준비가 끝난 상태를 기다릴 수 있는 준비 Promise를 제공한다.
4. 이동하는 점과 선·도형에는 동일한 카메라 변환을 적용한다. 확대·이동 때 점이 윤곽에서 떨어지지 않게 한다.
5. index.html에 모바일 반응형 플레이어를 만든다. 오디오 currentTime이 영상의 기준 시계다. 재생·일시정지·다시 보기·음소거·탐색을 지원한다. requestAnimationFrame은 한 개의 체인만 유지한다.
6. 로컬 브라우저와 FFmpeg로 렌더링할 수 있는 직접 작성한 render.mjs를 제공한다. 렌더 도구는 프레임 캡처·인코딩 용도로만 사용한다. 2250프레임을 스트리밍하고 큰 PNG 프레임 폴더를 만들지 않는다.
7. 10개 구간의 대표 프레임과 글자 변형·폰·중간 훅을 검토한다. 앞으로 → 끝 → 처음 → 같은 시간으로 탐색했을 때 픽셀이 같은지 확인한다.
8. 첫 결과를 first-pass 폴더에 보존한다. 첫 결과를 만들 때 기존 Sol 완성 코드나 영상을 읽지 않는다. 오류가 있으면 첫 결과와 문제를 기록하고, 수정본은 revision-01로 분리한다. 코딩 단계 시간과 렌더 대기 시간을 나눠 기록한다.
9. 결과 MP4는 H.264/yuv420p, AAC, 1080p60, 37.5초, 웹 재생용 faststart로 출력한다. 실제 사용 모델명과 실행 설정, 수정·실패 기록을 사실대로 보고한다.
10. 외부 게시·유튜브 업로드·이메일 전송은 하지 않는다. 로컬 결과와 소스 경로를 제공한다.

실행 중 비용이 드는 새로운 서비스가 필요하면 임의 호출하지 않는다. 제공된 입력과 로컬 도구만으로 완성하라.
