# Opus 5.5 실행 준비

이 묶음은 공통 프롬프트와 같은 입력 에셋만 담습니다. 완성된 Sol 모션 소스와 결과 영상은 포함하지 않습니다.

1. ZIP을 기존 HyperFrames/스킬 프로젝트 밖의 새 폴더에 풉니다.
2. Claude Code에서 해당 폴더를 열고 사용 모델을 Opus 5.5로 선택합니다. 계정에 표시되는 정확한 모델 ID와 추론 설정을 실행 기록에 남깁니다.
3. 아래 시작 문장을 입력합니다. common-prompt.md를 그대로 읽고 실행해야 합니다.

> common-prompt.md를 읽고 inputs의 동일 에셋으로 모션그래픽을 제작해 주세요. 이 작업에는 어떤 스킬·템플릿·이전 모션 코드·애니메이션 프레임워크도 적용하지 마세요. 프롬프트의 전체 요구사항을 따르고 first-pass에 첫 결과를 보존하세요. 실제 사용 모델명, 실행 시간, 오류, 수정 기록을 함께 남겨 주세요.

4. 첫 결과와 코드·렌더 로그를 먼저 보존합니다. 그 다음에만 아래 같은 수정 요청을 한 번 적용합니다.

> 첫 결과에서 한글 겹침, 휴대폰 비율, 점과 윤곽의 연결, 18.75초·30.46875초·31.40625초 음악 싱크, 앞뒤 탐색의 결정성을 확인해 주세요. 문제가 있는 부분만 고치고 결과를 revision-01에 보존하세요. 문제가 없으면 변경하지 말고 확인 결과를 기록하세요.

common-prompt.md와 opus55-ready-prompt.txt는 같은 내용입니다. 실행 전에 manifest.json의 SHA256과 입력 파일 해시를 확인합니다. 향후 GPT·Gemini 비교에도 같은 프롬프트 파일을 그대로 사용합니다.

이번 Sol 영상은 제작 중 연출과 검수 수정을 거친 실제 시연입니다. 이 고정 프롬프트가 그 모든 제작 대화와 바이트 단위로 동일했다는 뜻은 아닙니다. 공정한 첫 실행 비교를 하려면 GPT도 이 묶음으로 새로 실행해야 합니다. 현재 Opus·Gemini 결과나 비교 점수는 아직 없습니다.

음악은 이번 프로젝트에서 Sol이 직접 코드로 작곡한 트랙을 모든 모델에 공통 입력으로 제공합니다. 모션과 박자 싱크를 비교하기 위한 조건입니다. 음악 작곡 능력까지 별도로 비교하려면 동일 조건의 별도 실험을 진행합니다.

웹 채팅에서는 폴더 접근과 로컬 렌더 도구가 제공되지 않을 수 있으므로, 이 묶음은 로컬 파일을 사용할 수 있는 Claude Code 실행을 기준으로 합니다. 이 준비 작업에서는 Opus 실행이나 유료 생성 호출을 하지 않았습니다.
